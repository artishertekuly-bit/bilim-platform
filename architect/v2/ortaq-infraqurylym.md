# Ортақ инфрақұрылым v2

> **Белгілер:** ✅ бекітілген · ⏳ өлшем күтілуде

Бұл құжатта екі жүйе де пайдаланатын, бірақ олардың арасында дерек тасымайтын бөліктер жазылған.

## 1. Шекара ✅ (D12, D15)

**Ортақ:**
- Оқу режиміндегі оқулық корпусы: LightRAG индексі мен `chunk_meta` (§3).
- Кітапхана ретіндегі код: LLM gateway (§2), кіріс сүзгісі, модерация эвристикасы. Әр сервис оны өз ішінде қолданады.
- Мұғалімнің бір дабыл кірісі (§5): екі жүйе тек жазады, оны тек мұғалім панелі оқиды.

**Ортақ емес:** оқушы деректері, жауаптар, бағалар, меңгеру моделі, сессиялар. Бір жүйе жазған деректі екіншісі ешқашан оқымайды (D1).

**Деректер қоры деңгейіндегі бөлу:**

| Схема / кесте | Иесі | Кім қол жеткізеді |
|---|---|---|
| `examiner` | Examiner сервисі | Тек `examiner_svc` |
| `tutor` | Tutor сервисі | Тек `tutor_svc` |
| `rag` (LightRAG + `chunk_meta`) | Индекстеу контуры | Екі сервис — тек `SELECT` |
| `public.security_alerts` | Платформа | Екі сервис — тек `INSERT`; оқу — мұғалім панелі (RLS) |

Ережені сервис рөлдерінің құқықтары қамтамасыз етеді: `examiner_svc` `tutor` схемасына қол жеткізе алмайды, `tutor_svc` — `examiner` схемасына. `rag` схемасы Supabase API-ына ашылмайды.

## 2. LLM gateway ✅

Барлық LLM және embedding шақыруы осы модуль арқылы өтеді.

### 2.1. Тапсырмаға қарай модель

| Тапсырма | Модель класы | Режим |
|---|---|---|
| Модерация, Tutor тегтері, MCQ шешуші тексеру (Т7), Examiner 2-сатысының түсіндірмесі | Кіші, жылдам | Синхрон |
| Ресми бағалау (ЖИ, гибрид) | Күшті, бекітілген нұсқа (dated snapshot) | Синхрон, temperature 0 |
| Екінші бағалау (Т8) | Басқа күшті модель немесе бөлек промпт | Фондық |
| Tutor жауабы, Examiner SSE диалогы | Күшті | Stream |
| Пакет генерациясы | Күшті | Batch API |

Нақты модель атаулары конфигурацияда тұрады және өлшеу жүйесі (§6) арқылы таңдалады.

### 2.2. Prompt caching
Промпттың өзгермейтін бөлігі әрқашан басында тұрады: жүйелік промпт → рубрика → `reference_context` → соңында оқушы жауабы. Бір сұрақты көп оқушы тапсырғанда провайдердің префикс кэші бағалау құнын едәуір азайтады.

### 2.3. Лимит және кезек
- Модель бойынша token bucket (провайдердің RPM / TPM лимитіне сәйкес).
- Басымдық кезегі: ресми бағалау > Tutor > фондық генерация.
- 429 және уақытша қателерде экспоненциалды backoff (jitter-мен).
- API кілттерін ротациялау қолданылмайды: бір ұйымның кілттері ортақ лимитті бөліседі, ал лимитті бөлек аккаунттар арқылы айналып өту провайдер шарттарын бұзады. Лимит жетпесе, провайдерден лимит деңгейін көтеру сұралады.

### 2.4. Резерв провайдер
- Тек Tutor мен генерация үшін: негізгі провайдер істен шықса, резервке ауысады.
- Ресми бағалау модель ауыстырмайды: провайдер істен шықса, бағалау кезекте күтеді. Модель ауысса, балдар да өзгереді (bagalau Т4, Т5).

### 2.5. LightRAG
- Контекст `only_need_context = True` режимінде алынады.
- Tutor-да `hl_keywords` / `ll_keywords` тег классификаторынан беріледі, сондықтан LightRAG кілт сөз шығару үшін өз LLM шақыруын жасамайды.
- Әр сұрау workspace бойынша сүзіледі; тест және бенчмарк workspace-тері өндірістік сұрауларға кірмейді.

### 2.6. Кідіріс мақсаттары (p95)

| Жол | Мақсат |
|---|---|
| Examiner 1-саты код тексеруі (желімен бірге) | < 300 мс |
| Диалогтағы бірінші сөз (Examiner SSE, Tutor) | < 2 сек |
| Examiner 2-сатыдағы фондық түсіндірме | < 5 сек |

## 3. Оқулық корпусы және `chunk_meta` ✅

- `books/` ішіндегі кітаптар өзгертілмейді, LightRAG индексі қайта құрылмайды.
- Чанк мәтініндегі `[Оқулық: … | Тарау: … | Тақырып: §…]` тақырыптары бір рет талданып, кестеге жазылады:
  `chunk_meta (chunk_id, book, subject, grade, chapter, paragraph_no, paragraph_title, order_in_paragraph)`
- Индекстер: `(book, paragraph_no, order_in_paragraph)` және `(chunk_id)`.
- Жаңа кітап индекстелгенде `chunk_meta` сол контурда толтырылады.
- Осы кестеге Examiner-дің масштаб анықтауы ([ai_examiner §2](ai_examiner.md)) және Tutor-дың `tutor_nodes.paragraph_no` пен `textbook_order` алғышарт жиектері ([personarag §2.1](lightrag_personarag.md)) сүйенеді.

## 4. Клиентке дерек беру ✅

- Пакеттің `public` DTO-сы (тек `question_content`) мен `private` DTO-сы (кілт, рубрика, `reference_context`) — бөлек типтер.
- Клиентке, оның ішінде prefetch-ке, тек `public` барады. `public` типінде кілт өрістері жоқ екенін автоматты тест тексереді.
- Код тексеруінің бәрі серверде жүреді. Клиенттегі кез келген сүзгі тек ыңғайлылық үшін және серверде қайталанады.

## 5. Дабылдар ✅

`security_alerts (alert_id, source_system, student_id, severity, category, evidence_text, context_ref, status, created_at, resolved_by, resolved_at)`

- `source_system ∈ {examiner, tutor}`
- `category ∈ {TOXIC, TROLLING, PROMPT_INJECTION, PROFANITY, AGGRESSION}`
- `status ∈ {open, resolved, false_positive}`

Ережелер:
- Екі жүйе тек жазады; мұғалім панелі өз оқушыларының дабылдарын оқиды (RLS).
- Мұғалім панелінде дабылдар «Назар аударуды қажет ететін оқушылар» тізімі болып топталады (alert fatigue-тің алдын алу).
- Мұғалімнің шешімі әр жүйенің өз API-ы арқылы орындалады: панель Examiner-ге «страйкты жою + `grade_overrides`» командасын, Tutor-ға «бұғатты ашу» командасын жібереді. Жүйелер `security_alerts`-ті оқымайды. Бастапқы жазба сақталады.
- Екі жүйенің тәртіп ережелері әдейі әртүрлі: Examiner — емтихан адалдығы («2 мүмкіндік»), Tutor — оқушының қауіпсіздігі (бірден бұғат + мұғалім немесе таймер).

## 6. Өлшеу жүйесі ✅

Әр жүйенің өз алтын жиыны бар; әдістеме мен құралдар ортақ.

| Жиын | Көлемі | Метрика | Шегі |
|---|---|---|---|
| Examiner: ЖИ бағалайтын әр формат тобы | ~200 жауап, екі мұғалім белгілейді | ЖИ мен мұғалім келісімі (quadratic weighted kappa) | ≥ 0.70 және мұғалім–мұғалім келісімінен 0.10-нан артық төмен емес |
| Examiner: векторлық кэш | Алтын жиындағы жауап жұптары | Кэш соққысының дәлдігі | ≥ 99% |
| Tutor: тег классификаторы | 150–300 диалог қадамы | Әр класс бойынша F1 (`intent`, `error_type`, `arg_depth`, `evidence_mode`) | ⏳ алғашқы өлшемнен кейін бекітіледі |
| Retrieval | 100 сұрақ → күтілетін § | hit@5 | ⏳ алғашқы өлшемнен кейін бекітіледі |

- **Регрессия қақпасы:** промпт, модель немесе рубрика өзгерсе, жиын қайта жүреді. Метрика шектен төмендесе, өзгеріс өндіріске шықпайды.
- **Shadow режим:** жаңа нұсқа нақты трафикті қатар бағалайды, бірақ оқушының балына әсер етпейді.
- **Дерек көздері:** `answer_log` үлгілері және `grade_overrides` (әр түзету — дайын белгіленген мысал).
- **D16:** ЖИ бағалайтын формат өз шегінен өткенше оның нәтижесі мұғалім растауымен ғана ресми болады.

## 8. Қазақ тілі ✅

- **Токен бюджеті:** провайдердің токенизаторымен нақты қазақ мәтіндерінде өлшенеді; күй блогы мен оқулық чанктарына бөлек бюджет бөлінеді. Оқушы күйі мен құрылымдық деректер ASCII ықшам кодпен беріледі.
- **Кэш шектерін калибрлеу:** алтын жиындағы жұптардан «бірдей балл» мен «әртүрлі балл» ұқсастықтарының таралуы алынып, `θ_hit` пен `θ_margin` кэш соққысының дәлдігі ≥ 99% болатындай таңдалады. Мұнда дәлдік бірінші тұрады: кэштің қате соққысы оқушыға қате баға болып түседі.
- **Болымсыздық белгілері:** `емес`, `жоқ`, етістіктің -ма/-ме/-ба/-бе/-па/-пе жұрнақтары. Жауап пен ең жақын жауапта белгілер сәйкес келмесе, кэш қолданылмайды. Тізім дерекпен тексеріліп толықтырылады.

## 9. Дерек қорғау ✅

- Оқушылардың көбі кәмелетке толмаған, сондықтан дерек тек қажетті көлемде жиналады.
- RLS: оқушы тек өз дерегін, мұғалім тек өз оқушыларының дерегін көреді.
- Дабыл дәлелінің мәтіні оқу жылының соңына дейін сақталады, содан кейін өшіріледі немесе анонимделеді (D14).
- `rag` схемасы Supabase API-ына ашылмайды; сервистер тікелей Postgres қосылымымен, өз рөлдерімен қосылады.
